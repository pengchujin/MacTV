# 电视遥控器反向控制 Mac（试验功能）

本功能自 v0.1.2 提供。安装后，在设置中开启「用电视遥控器控制 Mac」。默认关闭；不使用 ADB 或 Wi-Fi 作为运行时控制通道。

## 行为

- 接收电视地址 0 发给本机播放设备地址 4、8 或 11 的 CEC User Control Pressed / Released。
- 播放、暂停、停止、上一首、下一首交给 Mac 当前媒体播放器。播放与暂停分别发送，不使用同一个切换命令代替。
- 媒体模式下确认键切换播放/暂停。部分 Mac 同时将电视确认键处理成 Return，可能操作前台 App；本功能不拦截这种系统行为。
- 媒体模式下左为上一首，右为下一首，上/下为 Command–Shift–Tab / Command–Tab 切换应用。设置用两段式控件切换媒体和鼠标模式，不再提供独立按键开关。
- 如果电视转发音量键（或启用上/下映射），尝试调整当前 Mac 输出设备的软件音量或静音；不支持时明确提示。不会把收到的音量键再次发回电视。
- 通常电视遥控器音量键直接调整电视音量，电视不会把这些按键转发给 Mac。HDMI 输出通常也没有可写的软件音量。

## 实机验证（2026-09-17）

M4 Mac mini、macOS 27、REDMI MiTV-MFFU1。使用 ADB `input keyevent` 在电视端模拟按键，实际传输仍经过 HDMI-CEC。用户手持遥控器的确认键已在电视发送日志与 Mac 接收状态中观察到；其他品牌电视尚未验证。

| 验证 | 结果 |
| --- | --- |
| 电视暂停键 127 | 收到 `04:44:46`、`04:45`；QuickTime 从播放变为暂停 |
| 电视播放键 126 | 收到 `04:44:44`；QuickTime 从暂停恢复播放 |
| 电视确认键 23，开启映射 | 收到 `04:44:00`；QuickTime 切换为暂停 |
| 退出试验版后再发暂停 | QuickTime 继续播放，作为对照 |
| 电视音量减、加键 | 电视侧未记录对应发往 Mac 的 CEC 按键，因此未验证 Mac 音量调节 |
| 上一首、下一首、停止 | 解码与映射已实现，播放器实机效果待验证 |

测试使用本地静音 WAV，不修改播放器媒体库。现有正式版的签名、辅助功能权限保持不变。

## 实现与限制

- 只读轮询 DPCD RX 信息和缓冲区，不清除系统中断、不改逻辑地址，不申请电视或音响的身份。
- 以 RX 信息给出的长度读取，复读验证一致性；启动时丢弃旧缓冲区，拒绝发往其他设备、广播、非电视来源及不完整的按键。
- 相同缓冲区不会重复触发；需要可观察到的变化/松开才能识别下一次相同按键。轮询可能漏掉很短的按键，因此目前不保证长按连发。
- 发送/扫描期间暂停监听，切换连接后重新建立基线。接收通道和 macOS 共用，不能保证捕获每一个帧。
- 播放控制使用非公开 `MRMediaRemoteSendCommand`，兼容性随 macOS 和播放器变化。返回成功仅代表请求被接受，不代表播放器实际执行。

参考：[Linux DP CEC 接收实现](https://github.com/torvalds/linux/blob/master/drivers/gpu/drm/display/drm_dp_cec.c)、[AOSP HDMI-CEC 按键定义](https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/hdmi/HdmiCecKeycode.java)、[MediaRemote 接口声明](https://github.com/theos/headers/blob/master/MediaRemote/MediaRemote.h)。

## 确认键映射与播放器复测

用户反馈 Apple Music 与网页播放无效时，电视确实发出了 `04:44:00`，Mac 设置显示「收到电视按键：确认」，但「确认键切换播放/暂停」关闭。开启该选项后，通过电视端 `input keyevent 23` 复测：

- Apple Music：当前曲目从播放切换为暂停，播放控件状态已核实。
- Safari 的 B 站播放器：视频暂停在 00:23，再次确认后恢复至 00:27。此结果仅覆盖该浏览器和测试页面，不代表所有网页播放器。

试验版恢复原有遥控器图标，移除临时 `TV → Mac` 菜单栏标题。

## 方向键复测

2026-09-17，本机安装 Developer ID 签名并通过 Apple 公证的 0.1.2 (4)，开启「方向键控制切歌和音量」。电视端 `input keyevent 22`（右）对应 CEC `04:44:04`，Mac 诊断确认收到向右。首次测试 Apple Music 待播队列为空，无法切换下一首；临时插播一首歌曲后再次测试：

- 右键：《有何不可》→《河山大好》，Apple Music 曲目标题实际变化。
- 左键（`input keyevent 21`）：《河山大好》→《有何不可》，标题实际变化。
- 上/下映射为 Mac 输出音量；当前 HDMI 输出的软件音量能力限制仍适用，不声明电视音量已由方向键调节。

38 项单元测试通过；三个语言目录共 251 个键校验通过。用户仍需使用实体遥控器验证手感与长按行为。

### 控制模式

设置中的“控制模式”可选择“媒体控制”（默认）或“鼠标控制”，选择会保存。
媒体模式直接启用左右切歌、上下切换应用、确认键播放暂停；鼠标模式将方向键映射为轻按 6 点、长按连续加速的指针移动，确认键轻按松开后左键单击，按住至少 0.65 秒松开后右键单击，不会同时发出切歌或播放暂停命令。专用媒体按键仍控制播放。
鼠标控制需要现有的辅助功能授权，不重置权限；指针限制在有效显示器范围内。连续移动约每 20 ms 更新，按住 160 ms 后开始移动，并在 1.2 秒内从每秒 90 点平滑加速至 900 点。松开、切换模式、关闭功能、连接暂停、读取失败或权限失效时停止。由于硬件缓冲区无法区分重复的相同帧，单次按住最多连续移动 4 秒，需松开再按；主线程停顿超过 200 ms 也停止，避免恢复后跳跃。部分 Mac 的原生 CEC 输入仍可能同时产生方向键或 Return，先在空白区域验证。

本机菜单键调查：电视原始输入捕获到三次 KEY_COMPOSE 和一次 KEY_ENTER，同期 Mac CEC 监听没有对应按键帧；因此未添加猜测的菜单键映射，也未增加网络控制。

### 设置界面

常用设置仅显示电视与音响、键盘、电视遥控器三组。媒体和鼠标模式使用两段式切换，操作说明各一行。授权入口仅在需要时出现。连接帮助默认折叠，包含兼容性说明、重新检测、实时状态、查询按钮与通信记录，便于排查问题。

2026-09-17 长按实测：用户按右键约 3 秒并松开，再短按左键；Mac 捕获到 `04:44:04` → `04:45`、`04:44:03` → `04:45`。确认该电视会转发松开信号，长按期间未观察到不同的按键帧。

安装 0.1.2 (8) 后，电视端 `input keyevent --longpress 22` 经 HDMI-CEC 驱动实际 Mac 指针：记录到 14 次位置变化，总移动约 50.98 点，短时间内每步由约 2.2 点增加到 5.5 点；释放后停止，后续采样保持静止。未发送鼠标点击。41 项单元测试通过，包含释放事件、静态缓冲去重、加速、丢失释放上限和主线程停顿保护。

### 鼠标速度

鼠标模式提供 6 档速度，默认第 3 档，自动保存。连续移动速度倍率依次为 0.35、0.6、1、1.4、1.9、2.5，轻按距离依次为 2、4、6、8、10、12 点。调速时停止当前移动；加速曲线和松开、断连等停止保护保持一致。返回键映射为 Esc；鼠标确认键长按后松开执行右击。拖拽和滚动尚未加入。

### 确认与返回

确认键在鼠标模式下等待松开再判断短按/长按，避免右击前先左击。超过 4 秒的延迟释放、断连、切换模式或另一按键会取消待执行点击。CEC 返回键 0x0D 在两种模式下发送 Esc；它能否退出全屏取决于当前 App。媒体上下键不再调整音量，专用音量键仍保留音量语义。原生 macOS 可能同时处理 CEC 按键，此行为未被拦截。

0.1.2 (10) 本机验证：电视端 `input keyevent 20` 经 CEC 进入媒体模式映射后，前台 App 从 MacTV 切换到 Safari。44 项测试通过。长按确认右击和返回 Esc 的手持遥控器端到端效果尚待用户验证；未宣称系统原生 Return 的并发行为已消除。
